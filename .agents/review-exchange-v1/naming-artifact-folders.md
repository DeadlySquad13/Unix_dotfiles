# Naming Artifacts Folders

## Root Folders

So we'll have:

- Projects: `rut-Projects_artifacts`
  - `Projects/.artifact` for @creamsoda -> @salt raw artifacts sync
  - `Projects/.artifacts--processed` for @salt -> @creamsoda processed
  artifacts sync
- Documents: `rut-Documents_artifacts`
  - `Documents/.artifacts` for @creamsoda -> @salt raw artifacts sync
  - `Documents/.artifacts--processed` for @salt -> @creamsoda processed
  artifacts sync

Also note that I've changed to artifact**s** everywhere except for
`Projects/.artifact`. I prefer plural in this context, Projects are too
expensive to change right now (updating sync directory takes a lot of time)
but it's considered legacy.

In scope of our task Projects' artifacts will be used.

## Project-local Folders

Let's process evidence: `node_modules ->
/zsalt/shared-/@creamsoda/Projects/.artifact/auto-hub/CurrentTask1/node_modules`

- auto-hub project, CurrentTask1 worktree has node_modules inside. Same way
with any worktree in a auto-hub project. And each project in Projects folder
too.
- each node_modules is then symlinked into `.artifact` folder at the root of
`Projects` to a mirrored location:
`Projects/.artifact/auto-hub/CurrentTask1/node_modules`

We're now introducing similar process, extending node_modules with a custom
folder sync:

- in each project root (Projects/auto-hub folder for instance) we would have
some kind of artifacts we want to sync. We called them `.local-artifacts`
- then each local artifacts folder from a bunch of projects will be synced to
the `Projects/.artifacts` in a same mirrored-way. We would get
`Projects/.artifact/auto-hub/.local-artifacts`

node_modules and .local-artifacts cover @creamsoda -> @salt

With our review system we also need @salt -> @creamsoda simplex. So we
introduce one more directory: `Projects/.artifacts--processed`

- It has same mirrored system like `Projects/.artifacts--processed` that has
all projects in a centralized manner. For instance auto-hub processed
artifacts: `Projects/.artifacts--processed/auto-hub`
- From a centralized location it would then be synced to projects local
directory for easier consume by an agent:
`Projects/auto-hub/.artifacts--processed`

So both root-anchored and project-anchored ignored directories exist. But
`.local-artifacts` are actually only project-anchored and root-anchored
directory is called `.artifacts--processed`.

`.local-artifacts` store project-based raw artifacts, `.artifacts--processed`
store project-based processed artifacts. In our case we work with review so
we'll have directories: `.local-artifacts/review`,
`.artifacts--processed/review` (I see youname this folder `review-exchange` in
plan, I think just `review` is better)

### Local Artifacts

Decided to name them local to differentiate from potential `shared-artifacts`
that we may want to share with others. Also it separates existing artifacts
(like node_modules generated by team working under project) from our personal,
local, artifacts.
