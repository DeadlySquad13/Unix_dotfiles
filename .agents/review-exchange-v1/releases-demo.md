# Демо: раздел «Релизы» в AutoHub

## План

1. Рассказать зачем раздел
2. Показать как создаются релизы

## Зачем нужен раздел

Раздел Релизы в AutoHub позволяет для того чтобы удобно собрать релиз из feature-веток в релизную ветку.

## Перед демо

- **Вход в AutoHub под пользователем с доступом к демо-проекту** — Иначе список проектов пуст
- **Проект настроен: GitLab ID, Jira prefix, default branch** — Без этого не подтянутся версии Jira и ветки
- **В GitLab есть feature-ветки с префиксами** `feature/`, `fix/`, `hotfix/`, `refactor/` — Иначе branch picker пуст
- **В Jira есть версия с задачами и release task** — Для автоподстановки при создании и панели «Задачи из JIRA версии»

## Навигация: как попасть в релизы

Релизы открываются **из проекта**.

1. Проекты
2. У нужного проекта — кнопка с иконкой ракеты **«Создать релиз»** (ведёт на страницу релизов проекта)

## Страница 1: Релизы проекта

### Что на экране

1. Шапка проекта с названием и информацией
2. Блок «Версии проекта JIRA», в нем
   - таблица версий из Jira
   - кнопка "Подставить" - заполняет форму создания релиза:
     - версию;
     - JIRA Release URL;
     - JIRA Release Task.
3. Блок «Создать новый релиз»
   - версия релиза
   - ссылка на версию в Jira
   - ссылка на задачу релиза

   Также можно увидеть имя релзной ветки - release/1.2.3

   Кнопка "Создать" создаёт релиз и ветку в GitLab и редиректит на страницу отдельного редлиза.

4. Таблица «Список релизов» (внизу)

   Здесь кликом можно перейти в конкретный релиз

   Релизы могут быть с такими статусами:

   - В работе - релиз открыт, можно добавлять MR
   - Финализирован - создан MR release/* в master, новые ветки только после расфинализации
   - Завершен - релиз закрыт после мержа в master

## Страница 2: Конструктор релиза (деталка)

### 1. Шапка релиза

- статус-бейдж;
- версия приложения и данные Jira;
- кнопка **«Удалить релиз»** (скрыта для завершённых).

### 2. Первый блок - «Задачи из JIRA версии» (сворачиваемая панель)

Блок показывает задачи из Jira и связанные с ними ветки. Можно чекбоксом выделить вектку и нажать кнопку "Создать МР для выбранных веток"

### 3. Второй блок - выбор веток из гитлаб для релиза

Выводит все ветки полученные из гитлаба, и можно также создать мр - выбрать втеку, нажать кнопку.

### 4. Таблица MR релиза

Отображает созданные МРы в рамках релиза и их состояния. Также отображается статус МРа - можно ли его вливать, и данные о пайплайне. Статусы обновляются автоматически (поллинг), перезагрузка страницы не нужна.

### 5. Флоу работы с релизом

1. Создаем МРы в релизную ветку через выбор веток и нажатие кнопки "Создать МР для выбранных веток"
2. Вливаем Мры. Если необходимо, удаляем, или ревертим.
3. Задаем будет ли МР с squash или нет, и задаем squash сообщение.
4. После добавления и влития веток, мы можем финализировать МР, то есть создать МР в мастер. Сам МР в мастер надо влить вручную.
5. Затем после ручного влития МРа в мастер, можно нажать "Завершить релиз" и Удалить ветки релиза
